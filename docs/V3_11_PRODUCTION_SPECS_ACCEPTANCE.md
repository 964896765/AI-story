# 刀码漫剧 V3.11 统一制作规格

基线为 `ba62680`。入口在「创作向导 → 立项与指挥 → 项目制作规格」。六阶段 24 步的顺序和名称沿用原工作流。

## 使用与数据合同

1. 在当前项目录入集数、单集目标时长、画风、画幅、宽高、帧率、发行平台和地域、预算币种与金额、制作限制。点「保存规格新版本」。可以保存未填完的草稿。旧浏览器备注可显式复制，字段由人工确认。
2. 为分镜和故事圣经选择同一规格版本。故事圣经可用「填写固定时长与画风」把该规格值填入当前草稿。版本待审批时核对必填内容、规格能力、集数、目标时长和分镜的绑定；启用 Guardian 时也核对风格。源剧本、分集、人物、场景和模型输入计划可以选择记录各自制作版本。复用旧创作资产不会修改其绑定。
3. 使用批准计划生成候选、配音和时间轴。任务读取固定 ID、版本序号和 SHA-256。候选、装配和渲染核对画幅，整剧渲染还核对时间轴的规格引用和总时长。导演计划保存其输入规格；历史计划继续读取原版本。质检记录保留规格标识，交付重新检查发行范围。新 ZIP 的 `production_spec.json` 记录版本、哈希和发行技术字段。
4. 选择两版比较可查看字段差异、可能影响的模块及固定基线版本的记录数。恢复历史版本会追加新版本。保存规格和审批各用独立流程，单独保存新规格不会改变镜头合同、任务、成片或已批准计划。

PostgreSQL `0017` 增加 `production_specs` 与导演计划的规格外键。同项目版本号及请求键唯一，写入使用项目行锁和期望版本。SHA-256 按排序 JSON 计算业务设置；导入的浏览器备注是独立历史依据，预算、限制和原备注不写入发行 ZIP。规格参与镜头合同哈希。显式用另一版本重新批准时，系统会按新合同处理候选。当前项目的一般显示可读最新规格，生产读取固定版本。

## 边界

- 现有本机引擎支持 24 fps、720×1280、1280×720 或 720×720。其他分辨率和帧率可登记在草稿，相关审批会阻断。当前规格允许 1–50 集、单集 0.5–600 秒，画幅和时长兼容规则沿用本机生产参数。发行沿用本地 MP4 和 ZIP。
- 尚未启用规格中心的项目沿用兼容路径。建立首份规格后，新故事圣经审批与新导演执行计划须有完整固定规格。历史批准件、独立试制和普通剪辑沿用原任务入口。画幅、时长等生产约束由固定版本生效。
- 预算与限制用于本轮版本化记录。真实调用继续关闭，现有付费闸门独立，项目规格不会启用模型或提升实际支付限额。Agent、AI 图片和 AI 动态视频仍属后续阶段。

## 实际验收

- 最终后端 167 项通过、0 失败、0 跳过，用时 311.22 秒。空库迁移至 `0017`、Alembic 模型比对、Vue 类型检查、Vite 生产构建均通过。并发保存测试确认两个相同起点的更新只成功一个。保留一条 Starlette/httpx 上游弃用提示。 [JUnit](v3-11-backend.xml)
- Chrome 保存草稿、显式导入旧备注、完成 v2、改版 v3、恢复为 v4。刷新浏览器和启动独立应用进程均从 PostgreSQL 读回原数据。缺项、分镜混用规格、错误画幅及发行地域均被拦截。分镜、候选、导演与交付页面显示固定的 v2。 [规格中心](v3-11-spec-center.png) · [影响比较](v3-11-spec-impact.png) · [导演](v3-11-spec-director.png) · [交付](v3-11-spec-delivery.png)
- 实际 FFmpeg 候选为方形 720×720。改为竖屏、再恢复规格后，原批准镜头合同的 SHA-256 仍一致。旧规格继续完成导演审批、合成、质检与授权交付。ZIP 为 227,806 字节，整包哈希通过，解包核对固定规格 v2。旧浏览器备注仍可读取，外部调用为 0。 [专项浏览器记录](v3-11-spec-browser.json)
- 六阶段 24 步导航、旧 Guardian 两集十镜、原总导演渲染与返工均通过隔离 Chrome 回归。原 Guardian 用例实际返工一镜、复用九镜并验证 30 张交付证据。 [兼容回归](v3-11-legacy-browser.json)
- 生产库升级前，在独立数据库和目录核对 7 个项目、13 项素材和 120 个文件，所恢复素材的 Range 返回 206。演练 `0016 → 0017 → 0016 → 0017` 后升级本机。新版规格接口与向导返回 200，Worker 在线，真实模型执行关闭，默认真实额度为 0。 [恢复与迁移](v3-11-recovery.json) · [本机状态](v3-11-readiness.json)

## 回滚

等待业务任务结束并保存当前 PostgreSQL 和 `data` 文件快照，运行 `scripts/stop.ps1`。空规格表时可在 `backend` 使用 `..\.venv\Scripts\alembic downgrade 0016`，回退本次提交，重新构建并用 `scripts/start.ps1 -Production` 启动。已有规格时迁移会拒绝直接删表。保留当前数据，把升级前的配对数据库和文件还原到独立目录，在该恢复环境运行 `ba62680`。
