# P7 故事圣经与跨集连续性

以 P6 提交 `da310a9` 为基线，在现有创作资产版本链中增加故事圣经和分镜字段。三集自编样本覆盖本地计划、规则检查和人工批准。模型生成式分集、分镜与跨镜头视觉一致性还需独立验收。

## 实现

- 故事圣经包含主题、世界观、叙事规则、主线时间轴、伏笔与回收。每集固定总剧本、分集和分镜版本，应用校验项目边界与引用类型。
- 每集可记录角色在开场和收尾的服装、道具、人物状态及场景版本。连续性检查定位跨集变更、总时长偏差、重复镜头 ID、无效剧集和伏笔顺序。写明剧情衔接理由的状态差异标为人工复核项。
- 分镜编辑增加稳定 ID、景别、机位、运镜、光线、构图、对白说话者/时长、情绪、声音、转场及制作策略。已有分镜请求哈希兼容，保存新版本才写入新增信息。
- 人工批准追加固定版本，保存复核意见、审核规则和固定来源。已有批准版本的内容和检查结果不随被引用资产的新版变化。

## 实测

- 独立 PostgreSQL 后端全量回归 106 项通过，0 项失败，0 项跳过。覆盖 0008 迁移、旧版分镜请求兼容、说话时长越界拦截、三集时长和衔接、人工批准幂等、旧引用保持及批准后原分镜更新。保留 1 条 Starlette/httpx 上游弃用提示。 [后端结果](p7-backend-tests.xml)
- Vue/TypeScript 检查与 Vite 生产构建通过。Chrome 经实际 HTTP 创建三集固定制作计划、检查实际 JSON 结果并用键盘批准。首次自动化在剧本下拉项加载前填写，调整等待条件后复验通过，无浏览器异常。 [浏览器证据](p7-browser-acceptance.json) · [审核截图](p7-series-review.png)
- 三集证据是人工创作和本地规则评估。没有发出真实模型请求或产生 API 费用。计划时长是镜头计划字段，实际成片时长待后续生产验证。
- 0007 快照在独立数据库和目录完成恢复核验，覆盖 7 个项目、13 条素材及 115 个关联文件。0007↔0008 独立演练通过，原工作台迁移到 0008 后重启。 [备份和迁移](p7-backup-migration-acceptance.json)

## 限制与回滚

- 连续性根据用户声明的数据与固定引用检查。视觉匹配、空间关系和对白语音时长仍需实测，计划里标注的制作策略等待生成和时间轴阶段接入。
- 故事圣经使用当前或显式加入的历史版本，跨季协同编辑和大批量计划尚未压测。
- 有故事圣经时，0008 拒绝直接删约束并降级。停写并备份当前库及文件后，在独立数据库恢复 0007 备份，并配套使用 P6 代码。保留 0008 数据供后续恢复。后续为生成候选与选用、算力调度和真实样片的预算守门。
