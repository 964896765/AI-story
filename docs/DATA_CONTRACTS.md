# V2.0 数据契约

## 项目、素材与版本

项目是 API 和数据库的业务归属边界。素材的 UUID、存储键、SHA-256 和授权说明构成当前导入记录。既有渲染按任务输入快照读取，创作引用固定到 `story_versions.id`。历史恢复追加版本，写入使用期望版本检测冲突，同一请求键若用于不同参数则返回 409。

## 本地任务

FastAPI 提交 PostgreSQL 任务，独立 Worker 以数据库 advisory lock、行锁和有效租约校验领取权。任务状态和尝试记录分开。HTTP 断线后可重读任务、事件及尝试。实际编码完成、媒体校验和发布后可下载成片。数据库 0006 允许无媒体资产的文本任务，旧媒体路由保留素材要求。

## 文本治理

供应商配置与项目预算独立。每次文本调用锁定源版本、配置、报价及提示词版本。发送前预留上限，响应先落库再核算。发送状态不明确时占用不释放，凭证对账有审计流水。账本使用币种与百万分之一货币单位，费率使用十进制。用量核算、账单确认、退款和模拟额度各自有明确语义。

队列执行完成可进入待审。只在指定草稿版本人工批准后追加正式剧本与分集大纲，生产批次固定引用认可的版本。手工编辑、拒稿、费用登记均保留调用链。

## 媒体分析与审核

分析任务固定素材 ID、原件 SHA-256、参数、引擎及工具版本。按步骤执行，成功产物经尺寸、哈希和适用的流/格式检查后与任务结果写入数据库。缓存命中仍复核 SHA-256。输出时间用相对容器原点的整数微秒，部分原始字段保留流时间基和源起点。

修订表固定素材、分析任务、候选帧及人工审核内容。字幕和人工证据按半开区间关联镜头。队列产物和审核快照分别保留，采纳动作另行创建固定 P4 版本。切镜表示画面边界，剧本和人物身份由人工确认。 [解析验收](P6_ACCEPTANCE.md)

OCR 分析结果的 `ocr.frames` 记录真实采样时间、原识别文本、行和帧产物索引。审核快照可保留 `ocr_samples`，每条用一个微秒宽的区间关联采样位置与所在镜头。人工校对保存在原有 `evidence` 中，带明确的人工来源及可编辑的时间范围。历史快照可缺少 `ocr_samples`。 [OCR 验收](P6B_OCR_ACCEPTANCE.md)

## 制作、交付与经营

故事圣经、时间轴依托创作版本表。每次时间轴渲染固定快照、24 fps 整数帧、素材 ID 与哈希。整剧任务在渲染成功后才启动技术质检。阻断问题需要返工，可接受告警通过文件哈希和人工意见复核。新批次保留未改且通过完整性检查的既有结果引用。

作品目录和素材授权保持可追踪历史。交付前核对权限地域、平台及时间，以固定版权版本和实际成片哈希写入 ZIP 清单。渠道规则独立版本化。人工发行事件不代表平台自动发送。结算按账号范围及凭证号去重，金额以整数 micros 保存，按币种汇总，估算或未知金额单独记录。
